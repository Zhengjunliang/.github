# Contributing

Issues and pull requests are welcome in every repository of this account.

## Issues

- Use the form that fits: a bug report, a feature request or a question. Search open and closed issues first.
- A security vulnerability never goes in a public issue: see SECURITY.md.

## Pull requests

- For anything larger than a typo, open or pick an issue first, so the change is agreed before it is written.
- Set up the repository as its README says before the first commit: that installs the hooks that check commits and files, and names the checks a pull request must pass.
- One topic per pull request, on a branch rebased onto `main`; history stays linear, with no merge commits.
- Commit messages follow Conventional Commits, in English.
- The pull request says what changed, which issues it closes (`Closes #n`, one line per issue; `Refs #n` for an issue it advances without meeting every criterion), and how it was verified, as criterion → evidence: a command and its result, a test, a screenshot.
- Everything written into a repository is in English: code, comments, documents, commit messages and issues.

## Licence and conduct

A contribution is licensed under the repository's licence (GitHub Terms of Service, section D.6). CODE_OF_CONDUCT.md applies in every repository of this account.
